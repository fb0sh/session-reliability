## 1. Timestamps

All timestamps are offset-aware ISO 8601 timestamps.  The implementation emits
UTC timestamps such as:

```text
2026-09-30T22:35:50+00:00
```

Values with `Z` are also accepted.  Timestamps are strings or `null`, never
floating-point epoch values.

## 2. IDs

### Session ID

```text
sr-YYYYMMDD-HHMMSS-<4 hex chars>
```

Example:

```text
sr-20260930-223501-a7f3
```

### Task ID

```text
task-YYYYMMDD-HHMMSS-<slug>
```

Example:

```text
task-20260930-223550-fix-downloader
```

Slug generation:

1. lower-case title/objective,
2. convert runs of non-alphanumeric characters to `-`,
3. trim leading/trailing `-`,
4. truncate to 40 characters,
5. fall back to a random four-character hex value.

Task IDs must be unique.  The CLI accepts an explicit `--task-id`; if an
existing task uses it, creation fails.

### Step and operation IDs

```text
step-1, step-2, ...
op-1, op-2, ...
```

They are unique inside a task.

## 3. Schema versions and compatibility

Every structured state file has:

```json
{
  "schema_version": 1
}
```

Compatibility policy:

| Version on disk | Behavior |
|---|---|
| `1` | normal read/write |
| `< 1` | reject as invalid state |
| `> 1` | reject with a clear unsupported-future-schema error; never silently overwrite |

V1 does not implement event-sourcing rebuild or automatic schema migration.
A future version must add a deliberate migration step.

## 4. Store index schema

Path:

```text
<store>/index.json
```

This file is a fast-discovery cache only.  It is never authoritative.

```json
{
  "schema_version": 1,
  "tasks": {
    "task-x": {
      "title": "Fix downloader",
      "status": "in_progress",
      "current_step": "step-2",
      "owner_session": "sr-A",
      "dirty": false,
      "updated_at": "2026-09-30T22:40:00+00:00"
    }
  },
  "sessions": {
    "sr-A": {
      "status": "active",
      "active_task": "task-x",
      "last_seen_at": "2026-09-30T22:40:00+00:00"
    }
  }
}
```

If the index is missing, invalid JSON, invalid current-version schema, or has an
invalid `tasks` / `sessions` shape, it can be rebuilt from task and session
files.  If it uses a future `schema_version`, do not overwrite or downgrade it.

## 5. Session schema

Path:

```text
<store>/sessions/<session-id>.json
```

```json
{
  "schema_version": 1,
  "session_id": "sr-20260930-223501-a7f3",
  "native_session_id": null,
  "status": "active",
  "active_task": null,
  "started_at": "2026-09-30T22:35:01+00:00",
  "last_seen_at": "2026-09-30T22:35:01+00:00"
}
```

Fields:

| Field | Type | Required | Notes |
|---|---|---|---|
| `schema_version` | integer | yes | must be `1` |
| `session_id` | string | yes | generated by this skill |
| `native_session_id` | string or null | yes | optional runtime metadata, never authoritative |
| `status` | string | yes | see enum below |
| `active_task` | string or null | yes | task currently bound to this session |
| `started_at` | ISO timestamp | yes | session creation time |
| `last_seen_at` | ISO timestamp | yes | refreshed on init/resume/attach |

Allowed session statuses:

```text
active
idle
closed
expired
```

## 6. Task state schema

Path:

```text
<store>/tasks/<task-id>/STATE.json
```

This is the authoritative machine-readable current state.  If it is corrupt,
the recovery path may also contain `RECOVERY_REQUIRED.md` as a sidecar marker;
the damaged `STATE.json` is never overwritten by that marker.

```json
{
  "schema_version": 1,
  "task_id": "task-20260930-223550-fix-downloader",
  "title": "Fix downloader",
  "status": "in_progress",
  "revision": 4,
  "objective": "Make the downloader reliable.",
  "current_step": "step-2",
  "steps": [
    {
      "id": "step-1",
      "title": "Analyze logs",
      "status": "completed",
      "summary": "404 handling is missing.",
      "created_at": "2026-09-30T22:35:55+00:00",
      "started_at": "2026-09-30T22:36:00+00:00",
      "completed_at": "2026-09-30T22:37:00+00:00"
    }
  ],
  "next_actions": [
    "Implement retry/backoff"
  ],
  "owner_session": "sr-20260930-223501-a7f3",
  "lease_expires_at": "2026-09-30T22:55:00+00:00",
  "lease_duration_seconds": 900,
  "dirty": false,
  "active_operation": null,
  "operations": [],
  "requirements": [
    "Handle 404 responses."
  ],
  "constraints": [
    "Use Python stdlib only."
  ],
  "success_criteria": [
    "A fresh session can resume safely."
  ],
  "facts": [
    {
      "summary": "404 responses currently raise an unhandled exception.",
      "recorded_at": "2026-09-30T22:36:30+00:00"
    }
  ],
  "decisions": [
    {
      "summary": "Use retry with exponential backoff.",
      "recorded_at": "2026-09-30T22:36:45+00:00"
    }
  ],
  "blockers": [
    {
      "summary": "Package index temporarily unavailable.",
      "recorded_at": "2026-09-30T22:38:00+00:00",
      "resolved": false
    }
  ],
  "important_context": [
    "Log file: /var/log/app.log"
  ],
  "created_at": "2026-09-30T22:35:50+00:00",
  "updated_at": "2026-09-30T22:37:00+00:00"
}
```

Required fields:

| Field | Type | Notes |
|---|---|---|
| `schema_version` | integer | must be `1` |
| `task_id` | string | must match directory name |
| `title` | string | display title |
| `status` | string | task status enum |
| `revision` | positive integer | optimistic-concurrency guard |
| `objective` | string | durable objective |
| `current_step` | string or null | at most one main step |
| `steps` | array | step objects |
| `next_actions` | array of strings | immediate next actions |
| `owner_session` | string or null | only this session may run ordinary task mutations |
| `lease_expires_at` | ISO timestamp or null | lease expiry; auto-renewed on successful owner mutation |
| `lease_duration_seconds` | positive integer | optional for older V1 state; default 900; preferred duration used by heartbeat renewal |
| `dirty` | boolean | unresolved side effect/recovery flag |
| `active_operation` | string or null | operation id |
| `operations` | array | operation objects |
| `facts` | array | confirmed findings |
| `decisions` | array | recorded decisions |
| `blockers` | array | current blockers |
| `important_context` | array of strings | recovery-relevant context |
| `created_at` | ISO timestamp | creation time |
| `updated_at` | ISO timestamp | last mutation time |

Implementation also stores `requirements`, `constraints`, and
`success_criteria` mirrors for checkpoint rendering.  `TASK.md` remains the
human-facing durable definition.

`STATE.json.owner_session` is authoritative for task ownership.  A session's
`active_task` is convenience binding metadata; if they disagree, trust the task
state and repair/ignore the session binding accordingly.  Task takeover only
updates the relevant task binding and never marks a whole session expired.

Allowed task statuses:

```text
pending
in_progress
blocked
paused
completed
failed
abandoned
```

`unfinished` is not a status.  It is a filter covering:
`pending`, `in_progress`, `blocked`, `paused`.

### Progress rule

Do not use a subjective percentage as authoritative progress.  Derive it from:

```text
completed actionable steps / total actionable steps
```

Skipped steps are excluded from the denominator.

## 7. Step schema

```json
{
  "id": "step-1",
  "title": "Analyze logs",
  "status": "completed",
  "summary": "404 handling is missing.",
  "created_at": "2026-09-30T22:35:55+00:00",
  "started_at": "2026-09-30T22:36:00+00:00",
  "completed_at": "2026-09-30T22:37:00+00:00"
}
```

Required fields:

| Field | Type | Notes |
|---|---|---|
| `id` | string | unique within task |
| `title` | string | human-readable |
| `status` | string | step status enum |
| `summary` | string or null | concise result |

Optional fields are timestamp strings or `null`.

Allowed step statuses:

```text
pending
in_progress
completed
failed
blocked
skipped
```

Only one step may be `in_progress` at a time in normal operation.  The
`current_step` field points at the main step.

## 8. Operation schema

Operations are stored in `STATE.json.operations`.  `active_operation` is the
operation id currently unresolved/attended.

```json
{
  "id": "op-18",
  "description": "Install package X",
  "state": "running",
  "side_effect": true,
  "started_at": "2026-09-30T22:40:00+00:00",
  "completed_at": null,
  "result_summary": null
}
```

Required fields:

| Field | Type | Notes |
|---|---|---|
| `id` | string | unique within task |
| `description` | string | operation description |
| `state` | string | operation state enum |
| `side_effect` | boolean | true for external side effects |
| `started_at` | ISO timestamp or null | set when running |
| `completed_at` | ISO timestamp or null | set when finished |
| `result_summary` | string or null | concise outcome |

Allowed operation states:

```text
planned
running
succeeded
failed
outcome_unknown
```

Unresolved states are `planned`, `running`, `outcome_unknown`.  An unresolved
side-effect operation forces `dirty=true` until recovery explicitly finishes it.

## 9. Event schema

Path:

```text
<store>/tasks/<task-id>/EVENTS.jsonl
```

One JSON object per line, append-only:

```json
{"ts":"2026-09-30T22:35:50+00:00","type":"TASK_CREATED","task_id":"task-x","title":"Fix downloader"}
{"ts":"2026-09-30T22:36:00+00:00","type":"STEP_STARTED","task_id":"task-x","step_id":"step-1"}
{"ts":"2026-09-30T22:37:00+00:00","type":"STEP_COMPLETED","task_id":"task-x","step_id":"step-1","summary":"Root cause found"}
```

Required fields:

| Field | Type | Notes |
|---|---|---|
| `ts` | ISO timestamp | event time |
| `type` | string | event type enum |
| fields | any JSON value | type-specific |

Supported event types:

```text
SESSION_CREATED
SESSION_ATTACHED
TASK_CREATED
TASK_ATTACHED
TASK_DETACHED
STEP_STARTED
STEP_COMPLETED
STEP_FAILED
FINDING_RECORDED
DECISION_RECORDED
OPERATION_STARTED
OPERATION_SUCCEEDED
OPERATION_FAILED
OPERATION_OUTCOME_UNKNOWN
CHECKPOINT_CREATED
TASK_PAUSED
TASK_BLOCKED
TASK_COMPLETED
TASK_FAILED
TASK_ABANDONED
TASK_TAKEOVER
```

Implementation extensions:

```text
STEP_ADDED
STEP_BLOCKED
BLOCKER_ADDED
BLOCKER_RESOLVED
NEXT_ACTIONS_SET
CURRENT_STEP_CHANGED
TASK_STATUS_CHANGED
REQUIREMENTS_UPDATED
LEASE_RENEWED
STATE_CORRUPTION_DETECTED
```

A normal resume does not need to read all events.  Events are used for audit,
dirty recovery, and optional state-corruption assistance.

## 10. Markdown schemas

### `TASK.md`

Durable, infrequently changed definition:

```markdown
# Task: <title>

## Objective
...

## Requirements
- ...

## Constraints
- ...

## Success Criteria
- ...

## Metadata
- Task ID: ...
- Created At: ...
```

### `CHECKPOINT.md`

Compact recovery summary produced from `STATE.json` and `TASK.md`:

```markdown
# Recovery Checkpoint

## Objective
## Current Position
## Completed
## Confirmed Facts
## Decisions
## Current Step
## Next Actions
## Blockers
## Side Effects
## Unresolved Operations
## Important Context
## Recovery Rule
```

Keep it compact.  Do not copy the entire conversation.

## 11. Secrets

Never store passwords, tokens, API keys, credentials, private keys, or other
secrets in `STATE.json`, `CHECKPOINT.md`, `TASK.md`, or `EVENTS.jsonl`.
Redact or omit sensitive values at the source.  Persisted files must not be
treated as trusted code.
